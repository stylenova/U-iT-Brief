# U-iT Brief — клиентский опросник на Vue 3

Многоязычная (UA / RU) форма-бриф для сбора требований к разработке сайта.
Заявка отправляется в Telegram-чат через прокси-сервис, после чего пользователь видит уведомление и попадает на страницу с контактами.

## ✨ Возможности

- 13 секций брифа: контакты, цели, тип сайта, функционал, дизайн, страницы, контент, ЦА, технические требования, бюджет, сроки, поддержка, комментарии.
- Полная локализация: украинский и русский, переключение «на лету».
- Валидация на стороне клиента: красная подсветка обязательных полей, локализованные сообщения об ошибках под каждым полем, общая сводка ошибок над кнопкой.
- Удобный выбор даты старта через [`@vuepic/vue-datepicker`](https://vue3datepicker.com/) с локалью под язык интерфейса.
- После отправки: уведомление «Спасибо», очистка формы, автоматический редирект на страницу с контактами.
- Покрытие чистой логики (валидации) unit-тестами на встроенном `node:test`.

## 🚀 Установка и запуск

```bash
npm install        # установка зависимостей
npm run serve      # dev-сервер с hot reload (http://localhost:8080)
npm run build      # production-сборка в dist/
npm test           # запуск unit-тестов
npm run deploy     # сборка + публикация в ветку gh-pages
```

## 🧪 Тесты (TDD)

Логика валидации вынесена в [src/utils/validation.js](src/utils/validation.js) и покрыта тестами.
Запуск:

```bash
npm test
```

Покрыты сценарии:
- пустая форма → ошибки на всех обязательных полях;
- регулярка email — корректные и некорректные адреса;
- сообщения об ошибках корректно меняются между UA / RU;
- валидная форма → ошибок нет;
- условные поля «Другое» (`siteType`, `support`) требуют уточняющий ввод;
- строки из одних пробелов считаются пустыми.

## 🤖 Подключение Telegram-бота

Форма поддерживает два способа доставки заявки в Telegram. По умолчанию активен первый.

### Вариант 1 (по умолчанию): прокси через сторонний сервис

Используется внешний HTTP-эндпоинт, который принимает JSON и пересылает текст в Telegram-чат. URL эндпоинта задаётся в компоненте константой `API_URL`.

```js
// src/components/ClientQuestionnaire.vue
const API_URL = 'https://<provider>/<route>/<key>';
```

Преимущество — работает на статичном GitHub Pages без backend.
Минус — ключ виден в исходниках, поэтому стоит ограничить эндпоинт по реферреру / методу / частоте на стороне сервиса.

### Вариант 2: собственный PHP-обработчик

В [public/send-telegram.php](public/send-telegram.php) лежит готовый скрипт, который принимает `POST` с JSON формы и отправляет сообщение через [Telegram Bot API](https://core.telegram.org/bots/api):

```
POST https://api.telegram.org/bot<TOKEN>/sendMessage
```

Чтобы переключиться на PHP-вариант:

1. Разместить `send-telegram.php` на хостинге с PHP (любой shared / VPS).
2. Заполнить переменные `$bot_token` и `$chat_id` (значения **не коммитить** — храните в `.env` или в переменных окружения сервера).
3. В компоненте поменять `API_URL` на адрес своего скрипта.

> 🔐 Никогда не коммитьте реальный токен бота и ID чата — это эквивалент пароля. Используйте `.env`, переменные окружения или серверные секреты.

### Формат сообщения

Текст формируется методом `buildMessage()` в компоненте: HTML-разметка с emoji-разделителями секций. Язык сообщения совпадает с выбранным языком интерфейса.

## 🌐 Деплой на GitHub Pages

В `package.json` указан `homepage` и скрипт `deploy`:

```bash
npm run build && npm run deploy
```

`gh-pages` опубликует содержимое `dist/` в ветку `gh-pages` репозитория, после чего сайт станет доступен по адресу из `homepage`.

## 🔐 Безопасность

- Все обязательные поля валидируются и на клиенте, и должны проверяться на бэкенде, если используете PHP-вариант.
- В PHP-обработчике все пользовательские значения экранированы через `htmlspecialchars`.
- Не храните `bot_token` / `chat_id` в репозитории — выносите в окружение.
- Прокси-эндпоинт желательно ограничить по `Referer`, методу и частоте запросов.
